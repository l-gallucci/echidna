# Echidna 1.0.0

First GitHub Release of Echidna: a Python toolkit for metagenomic assembly
integrity, MAG quality assessment and chimera screening.

The installable distribution is **echidnaxomics**. The command, Python import
and `python -m` module remain **echidna**. The Python core uses only the standard
library; external tools and reference databases are installed separately.

## Included workflows

- **Assembly integrity:** `misassembly-wf` coordinates anvi'o misassembly
  detection, large-contig processing, optional read taxonomy and assembly
  filtering. The documented soft-clipping method applies to PacBio HiFi reads
  mapped to the assembly they produced.
- **MAG assessment:** `mag-quality-wf` coordinates CheckM2, quality tiering,
  GTDB-Tk, GUNC, optional per-contig taxonomy and MIMAG RNA screening, followed
  by chimera reporting and final organization. Binning is performed upstream.
- **Shared-contig resolution:** `check-shared-contigs` reports exact full-contig
  sharing, including reverse complements, and conflicting FASTA IDs. Optional
  policies exclude conflicting MAGs or remove lower-priority copies while
  preserving original FASTAs.
- **Checked cluster recovery:** alternatives from dRep secondary clusters or
  generic dereplication tables can replace excluded/trimmed representatives.
  Candidates are checked against every retained MAG. Reused sequence-linked
  contig taxonomy can gate selection by resolved-base coverage and taxonomic
  coherence. Both checks are repeated on the exported FASTAs.
- **Taxonomy reuse:** `classify-contigs --taxonomy-table` recomputes bin summaries
  for changed genome membership without rerunning the original classifier.
- **Snakemake:** bundled templates support optional overlap/taxonomy selection
  before final QC and can be exported with `setup-workflow --export-workflow`.

Other commands provide SSU taxonomy comparisons, RNA checks, zero-coverage
inspection, final report aggregation and environment/database setup helpers.

## Corrections and compatibility

This release includes strict native/legacy anvi'o input parsing, safer contig
identity matching, aligned-base depth calculations, propagation of external
process failures and explicit handling of missing evidence. Ambiguous raw
contig IDs associated with different sequences are rejected before ID-based
taxonomy aggregation; repeated identical IDs are classified once by the MMseqs
wrapper.

The per-contig classification table adds `sequence_sha256`, `contig_length` and
`taxonomy_rank`. Older tables can be regenerated from existing raw classifier
output and its matching original FASTAs without rerunning the classifier.
Assembly filtering consumes read-level risk tables; per-MAG chimera verdicts
are a different input. Read report columns by header and retain stable contig
identities. See the [changelog](https://github.com/l-gallucci/echidna/blob/v1.0.0/CHANGELOG.md) for the full change list.

## Validation and interpretation

Local validation passed **300 tests**, including actual execution and reruns
of the MAG workflows with synthetic inputs and fixture producers standing in
for expensive external tools. Source/wheel packaging, installation outside the
checkout and the strict documentation build were also checked.

These checks validate software behavior and file handoffs; a biological
end-to-end benchmark with the intended tools and databases remains required.
Shared-contig matching does not assess partial overlaps or ANI. Taxonomic
coherence is assessed at the supplied rank and configured thresholds, not as a
guarantee of biological purity. Trimmed genomes need new quality estimates.
The workflows run final QC on resolved genomes instead of transferring the
previous representative's reports.

Chimera verdicts remain report-only; organized folders are not automatically
filtered by `Chimeric` or `Check`. The explicit taxonomy acceptance gate in
overlap resolution is a separate operation. Quality tiers are project defaults
and only include the RNA criterion when that optional gate is requested.
